## 1. RPC（要回执的**动作**）

注册在 **`<房间名>-speaker`** 这个参与者上
（identity 由 `f"{bot_name}-speaker"` 拼出，房间名 ＝ bot 名）。
全部返回 JSON `{"ok": bool, ...}`。

| 方法 | 入参 | 返回 | 客户端 |
|---|---|---|---|
| `cc.playback.pause` | — | `{ok}` | ✅ |
| `cc.playback.resume` | — | `{ok}` | ✅ |
| `cc.playback.stop` | — | `{ok}` | ✅ |
| `cc.playback.replay` | `{fid?}` 不传＝当前段 | `{ok}` | ✅ |
| `cc.playback.seek` | `{delta}` **比例** −1…1 | `{ok}` | ✅ |
| `cc.playback.progress` | — | `{ok, active, played?, total?, fid?}` | ✅ |

⚠️ 两条容易写错的约定：

- **`ok: false` 不是错误**，是「这个动作现在做不了」（例：播完了还按暂停）。
  客户端要如实反映，但别当故障。
- **`total` 可以是 `null`** —— 音频还在生成、总长未知。
  **不许编一个分母**；客户端此时不画进度条，只报已播时长。

⚠️ 这一层**不做鉴权**：能进房间就说明已经拿到房间 token，
而 token 是 bot 自己签给指定用户的。在这儿再判一次 identity
只会多一处会跟签发逻辑跑偏的地方。

## 2. 参与者属性（**状态**，谁改了所有人都看得见）

| 键 | 谁写 | 谁读 | 含义 |
|---|---|---|---|
| `cc.bot.state` | `<房间名>-speaker` | 客户端 | bot 在忙什么（任务/步骤/耗时） |
| `lk.agent.state` | 语音助手 agent | 客户端 | `listening` / `thinking` / `speaking` |
| `cc.avatar.want` | 客户端 | agent | 用户想不想要数字人 |
| `cc.avatar.state` | agent | 客户端 | 数字人实际起没起来 |
| `cc.client.visible` | 客户端 | agent | app 在不在前台 |

## 3. 数据消息（**单向广播**，不要回执）

| topic | 谁发 | 谁收 | 含义 |
|---|---|---|---|
| `cc.bot.step` | `<房间名>-speaker` | 客户端 | 一条一条的过程轨迹 |

## 怎么选：RPC / 属性 / 数据消息

| | 用它当 | 判据 |
|---|---|---|
| **RPC** | 动作 | **调用方需要知道成没成** |
| **属性** | 状态 | 后来进房间的人也该看到当前值 |
| **数据消息** | 事件流 | 只对此刻在场的人有意义，丢了不要紧 |

⇒ 最容易选错的是**用数据消息做动作** —— 它是单向的，
「按了没反应」和「按了失败了」在那条路上长得一模一样。
